## 1. RocketMQ 整体架构？

**锚点**：官方文档 Architecture

- [ ] **及格**：四个角色——**NameServer / Broker / Producer / Consumer**；消息流转：Producer 发到 Broker 的某个队列，Consumer 从队列拉取
- [ ] **良好**：及格 + 能说出关键设计——**NameServer 无状态、彼此独立**（不用 Zookeeper，路由信息最终一致）；Broker 主从（同步/异步复制）；Topic 拆成多个 MessageQueue 提供并行能力
- [ ] **精通**：良好 + 能应对追问——**为什么不用 Zookeeper 而用 NameServer**（ZK 重、RocketMQ 只需要轻量路由，用 ZK 是过度设计）、Broker 宕机消息怎么办（主从切换 + 未消费消息仍在磁盘）、读写分离（主写从读）、NameServer 挂了影响什么

## 2. 消息模型：Topic / Tag / Queue / 消费模式？

**锚点**：官方文档 Concepts

- [ ] **及格**：**Topic → 多个 MessageQueue**（物理分区）；**Tag** 用于消息分类；消费模式——**集群消费**（队列分配给组内消费者，一条消息只被一个消费者处理）vs **广播消费**（每个消费者都处理全部）
- [ ] **良好**：及格 + 能解释——消费组（Consumer Group）的概念、队列数为什么影响**并行度**（一个队列同一时刻只被组内一个消费者拉取）、Tag 过滤 vs 队列级隔离的取舍
- [ ] **精通**：良好 + 能应对追问——**顺序消息怎么保证**（同一队列 + 顺序消费模式 + 单消费者）、为什么集群消费下**队列数就是最大并行度**、一个 Topic 多个消费者组互不影响（订阅关系独立）、广播消费的落点

## 3. 消费者机制：推拉 / 重试 / 幂等？

**锚点**：官方文档 Consumer

- [ ] **及格**：Push 与 Pull 两种模式（Push 底层也是长轮询拉取）；消费进度 **offset** 由消费者维护
- [ ] **良好**：及格 + 能说出——消费失败**重试机制**（重试 16 次，进**死信队列**）、消费端**幂等**的必要性（at-least-once 语义下可能重复投递）、消费进度存储位置（Broker 端 consumer offset 或本地文件）
- [ ] **精通**：良好 + 能应对追问——**消息丢失**的完整链路防护（生产端同步发送 + Broker 刷盘/主从复制 + 消费端手动 ack）、重复消费的典型场景（消费者宕机后 rebalance）、怎么实现**幂等**（唯一 ID + 去重表 / 状态机）、消费堆积时如何扩容（加消费者前提是队列数够）

## 4. 如何保证消息不丢？（可用性/可靠性）

**锚点**：官方文档 / 《RocketMQ 实战》

- [ ] **及格**：三段式防护——**生产端**：同步发送 + 失败重试；**存储端**：Broker 刷盘 + 主从复制；**消费端**：手动 ack，失败重试
- [ ] **良好**：及格 + 能解释细节——刷盘策略（**同步刷盘** vs 异步刷盘）与主从复制策略（**同步复制** vs 异步复制）各自的可靠性/性能取舍；`sendResult` 的 `sendStatus` 判断
- [ ] **精通**：良好 + 能应对追问——**保证不丢的最优组合**（同步发送 + 同步刷盘 + 同步复制 + 手动 ack 是代价最高的组合）、异步刷盘丢多少数据（刷盘间隔内断电）、顺序消息场景下 Broker 故障如何处理、消息补偿机制（定时扫描未确认消息）

## 5. 事务消息 & 延迟消息？

**锚点**：官方文档 Transaction Messages / Scheduled Messages

- [ ] **及格**：**事务消息**解决分布式事务（本地事务与消息发送的原子性）；**延迟消息**支持 18 个延迟等级（1s/5s/10s/…/2h）
- [ ] **良好**：及格 + 能说出流程——事务消息：发送 **half 消息** → 执行本地事务 → commit/rollback → 本地事务无结果时**回查**（check 回调）；延迟消息：按等级放入**延迟队列**，到期后转投真实 topic
- [ ] **精通**：良好 + 能应对追问——**为什么事务消息能保证最终一致性**（half 消息 + 本地事务 + 回查三段）、回查次数与超时、**事务消息与本地消息表方案**的对比、延迟消息的**精度限制**（固定等级，不能任意延迟时长）、事务消息是否影响吞吐
