## 高可用（镜像队列+Quorum）
高可用是什么->镜像队列->镜像同步->Quorum队列->集群模式->面试高频题
### 高可用是什么
高可用：单个节点故障时，消息不丢，服务可用。RabbitMQ通过集群+队列副本实现。
单节点风险
```
// 单节点 RabbitMQ：
// ① 宕机 → 全部不可用
// ② 持久化消息也可能丢（磁盘故障）
// ③ 无故障转移

// 需要：集群 + 队列数据多副本
```
### 镜像队列（Classic模式）
```
// 镜像队列（Mirrored Queue）：
// 一个主队列（master）+ 多个镜像（mirror）
// 数据同步到所有镜像节点
// 主节点挂了 → 镜像提升为主

// 配置（policy）：
rabbitmqctl set_policy ha-all "^" '{"ha-mode":"all"}'
// ^ 匹配所有队列，ha-mode=all：所有节点都有镜像

// 或者：
// ha-mode=exactly：指定副本数
// ha-mode=nodes：指定节点
```
镜像同步原理
```
// ① 消息写入主队列（master）
// ② 主节点同步给所有镜像（mirror）
// ③ 确认机制：
//    - 生产者确认等主节点（或按策略等镜像）
// ④ 主节点挂了：
//    - 从镜像中选一个新主（最接近主的）
//    - 队列继续服务

// 一致性级别：
// 同步到全部镜像才确认（强一致，慢）
// 主确认（弱一致，快）
```
镜像队列的缺点
```
// ① 同步性能损耗（每条都要复制）
// ② 所有镜像都有完整数据（存储翻倍）
// ③ 脑裂问题（网络分区）
// ④ 主从切换不够自动化（旧版本）
```
### Quorum队列（3.8+）
```
// Quorum 队列（仲裁队列）：
// 基于 Raft 共识算法
// 数据在多个节点复制（默认 3 个副本）
// 自动选主、自动恢复

// 是镜像队列的升级替代：
// ① 更稳定（Raft 共识）
// ② 自动故障转移
// ③ 数据强一致
// ④ 防脑裂
```
声明方式
```
// 声明 Quorum 队列
Map<String, Object> args = new HashMap<>();
args.put("x-queue-type", "quorum");      // 关键：类型
args.put("x-quorum-initial-group-size", 3);  // 3 副本（可选）
channel.queueDeclare("quorum-queue", true, false, false, args);
```
特点
```
// ① Raft 选举 Leader：挂了自动选新 Leader
// ② 多数派确认：多数副本写入才算成功
// ③ 防脑裂：需要多数派（分区时少数派不可写）
// ④ 只支持"经典队列"的功能子集：
//    - 支持死信、TTL
//    - 不支持独占队列、临时队列
// ⑤ 3.8+ 默认推荐
```
### 镜像 vs Quorum
| 对比        | 镜像队列   | Quorum 队列 |
| --------- | ------ | --------- |
| **算法**    | 主从复制   | Raft 共识   |
| **确认**    | 主/全部镜像 | 多数派       |
| **选主**    | 手动/半自动 | 自动 ✅      |
| **脑裂**    | 可能     | 防脑裂 ✅     |
| **数据强一致** | 弱/强可配  | 强 ✅       |
| **版本**    | 老方案    | 3.8+ 推荐 ✅ |
**Q:** "RabbitMQ 高可用怎么做？" 
**A:** "两种方案：① 镜像队列（老方案）：主从复制，主挂了选镜像提升，但同步开销大、可能脑裂；② Quorum 队列（3.8+ 推荐）：基于 Raft 共识，多数派确认、自动选主、防脑裂、数据强一致。生产推荐 Quorum 队列。"
### 集群模式
普通集群
```
// 多个节点组成集群（默认模式）
// ① 每个节点有"部分"队列（队列数据分布）
// ② 元数据共享（交换机、绑定全局可见）
// ③ 消息路由：请求转到队列所在节点

// 注意：
// 普通集群：队列数据只在所属节点
// 其他节点挂了不影响该队列（除非就是队列所在节点）
// 不算真正高可用（要镜像/Quorum 才多副本）
```
镜像/Quorum集群
```
// 在集群基础上 + 队列多副本
// 节点挂了 → 副本接管 → 高可用 ✅
```
集群注意点
```
// ① 节点通过 Erlang cookie 互联
// ② 集群至少 3 节点（多数派）
// ③ 磁盘节点 + 内存节点混合（磁盘节点存元数据）
// ④ 网络分区处理策略（pause-minority 等）
```
